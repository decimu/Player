# Replay Player

OBS で撮った録画（mp4）をすぐ見返して、そのままクリップを切り出すための Windows 向けデスクトップアプリです（Tauri v2 + React）。

Among Us の「タスクターンは録画 OK」な村で、

- **会議中**: 直前のタスクターンをすぐ見返す
- **試合後**: 良かった場面をクリップにして Discord に貼る

という使い方を想定しています。

## できること

- OBS の録画フォルダを指定すると、録画が新しい順・日付ごとに並ぶ
- 新しい録画（リプレイバッファの保存など）ができると **自動で開いて再生**
- OBS が書き込み中のファイルには「書き込み中」の印が出る
- 再生速度 0.25〜4 倍、1 コマ送り、5 秒 / 10 秒スキップ、0〜9 キーで 0〜90% に移動
- タイムラインにカーソルを乗せると、その位置の映像を小さくプレビュー
- **マーカー**（B キー）: 気になった場面に印を付けておける（ファイルごとに保存）
- **クリップ書き出し**（ffmpeg を使用）: I / O で範囲を決めて書き出し
  - **高速**: 再エンコードなしで一瞬。開始位置が少し前（直前のキーフレーム）にずれることがある
  - **高画質**: H.264 で再エンコードしてフレーム単位で正確
  - **10MB以下**: Discord の無料プランにそのまま貼れるサイズに圧縮（上限は設定で変更可）
- 書き出したクリップは「コピー」ボタンでファイルとしてクリップボードへ。Discord で Ctrl+V するだけで添付できる
- 動画ファイルやフォルダをウィンドウにドラッグ＆ドロップしても開ける

## 使い始める

1. **ffmpeg を入れる**（クリップの書き出しに必要。見るだけなら不要）
   コマンドプロンプトで次を実行し、アプリを開き直します。
   ```bat
   winget install Gyan.FFmpeg
   ```
   `ffmpeg.exe` をこのアプリと同じフォルダに置くか、設定画面で場所を指定しても使えます。
2. アプリを起動して「フォルダを選ぶ」から **OBS の録画フォルダ** を選びます。
   OBS の「設定 → 出力 → 録画 → 録画ファイルのパス」に出ているフォルダです。
3. 一覧から録画を選ぶと再生が始まります。

クリップは既定で `録画フォルダ\clips` に保存されます（設定で変更可）。

## 会議中に見返すための OBS 設定（おすすめ）

OBS の mp4 は **録画を止めるまでファイルが完成しない** ので、録画中のファイルはそのままでは再生できません。会議中に見返すには、次のどちらかを使います。

### A. リプレイバッファ（いちばん手軽）

1. OBS の「設定 → 出力」でリプレイバッファを有効にし、最大リプレイ時間を決める（例: 180 秒）
2. 「設定 → ホットキー」で「リプレイを保存」（Save Replay）にキーを割り当てる
3. OBS のメイン画面で「リプレイバッファ開始」
4. 会議が始まったらそのキーを押す → このアプリに Alt+Tab すると、直前の数分が自動で開いて再生されています

リプレイは録画と同じフォルダに保存されるので、追加の設定はいりません。

### B. 録画を分割する

OBS 30 以降には録画を分割するホットキー（Split Recording）があります。会議の開始時に分割すると、それまでの分が 1 本のファイルとして完成し、このアプリで自動的に開きます。録画自体は止まりません。

> 録画フォーマットは **H.264 の mp4** がおすすめです。HEVC / AV1 は PC によって再生できないことがあります。
> mkv で録画している場合は、OBS の「録画の自動再多重化」（mp4 に自動変換）を有効にしてください。

## ショートカット

| キー | 動作 |
| --- | --- |
| Space / K | 再生 / 一時停止 |
| ← / → | 5 秒戻る / 進む（秒数は設定で変更可） |
| Shift + ← / → | 1 秒戻る / 進む |
| J / L | 10 秒戻る / 進む |
| , / . | 1 コマ戻る / 進む |
| [ / ] | 再生速度を下げる / 上げる |
| 0 〜 9 | 0% 〜 90% の位置へ |
| Home / End | 先頭 / 末尾へ |
| ↑ / ↓ / M | 音量 / ミュート |
| F / ダブルクリック | 全画面（Esc で戻る） |
| R | 動画を再読み込み |
| I / O | 今の位置をクリップの開始 / 終了にする |
| Shift + I / O | 開始 / 終了の位置へ移動 |
| Q | 直前 15 秒をクリップ範囲にする |
| X | 範囲をクリア |
| E / Enter | クリップを書き出し |
| B | 今の位置にマーカー |
| N / Shift + N | 次 / 前のマーカーへ |
| ? | ショートカット一覧 |

## 開発

### 必要なもの

- [Node.js](https://nodejs.org/) 20 以上
- [Rust](https://www.rust-lang.org/tools/install)（stable）
- Windows: Visual Studio の「C++ によるデスクトップ開発」ビルドツール、WebView2（Windows 10/11 には入っています）
- そのほか OS ごとの準備は [Tauri の Prerequisites](https://v2.tauri.app/start/prerequisites/) を参照

### コマンド

```bash
npm install
```

```bash
npm run tauri dev
```

```bash
npm run tauri build
```

`npm run tauri build` でインストーラーが `src-tauri/target/release/bundle/` にできます。
手元に Rust を入れなくても、GitHub の Actions タブで「Windows ビルド」を手動実行すると、インストーラーを Artifacts からダウンロードできます（`v` で始まるタグを push したときも動きます）。

```bash
cargo test --manifest-path src-tauri/Cargo.toml
```

### 構成

| 場所 | 役割 |
| --- | --- |
| `src-tauri/src/files.rs` | 録画フォルダの一覧、クリップボードへのファイルコピー（Windows） |
| `src-tauri/src/media.rs` | 動画を `<video>` に流す小さな HTTP サーバー（127.0.0.1 限定・推測できないトークン付き URL・許可したフォルダの動画だけ配信・Range 対応） |
| `src-tauri/src/ffmpeg.rs` | ffmpeg の検出と、クリップ書き出し（進捗通知・キャンセル） |
| `src/lib/useFolderWatch.ts` | フォルダを定期的に見て、書き込み中の判定と新しい録画の検出 |
| `src/components/Player.tsx` | プレイヤー本体（キー操作、IN / OUT、マーカー） |
| `src/components/Timeline.tsx` | シークバー、範囲のドラッグ、ホバープレビュー |

動画の受け渡しに Tauri 標準の asset プロトコルを使っていないのは、Linux (WebKitGTK) では動画を再生できず、Windows でも 1 回の応答が 1MB までで数 GB の録画のシークに不利なためです。
